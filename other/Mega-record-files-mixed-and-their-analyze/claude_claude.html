7. Can Trust Be Forced / Accelerated?

What can be forced client-side (interceptor / extension)

  • Strip phone gates → account skips the gate UI (but SMS is still needed for real phone verification)
  • Block selfie verify → biometric check bypassed
  • Patch photo flags in responses → browser sees photos as clean even if server flagged them
  • Suppress kill signals → session survives longer
  • Accept-Language injection → UI in correct language

What CANNOT be forced client-side

  • CDN routing (gew vs normal) — 100% server-side decision based on Moumi's trust score for the account. Interceptor can detect but not change it.
  • Encounter visibility (whether others see you) — server ranking algorithm, no client hook.
  • popularity_level — server-assigned. Patching it in responses is cosmetic only.
  • Phone SMS verification — Moumi sends OTP to real number. Cannot be spoofed.
  • Photo CDN moderation — human/AI content review on Moumi's servers.

Chrome Extension vs CDP Interceptor

ApproachDetection riskCapability
CDP interceptor (current)Low — only Fetch domain enabled, no Runtime/DebuggerFull request/response read+modify
Chrome extension (webRequest API)High — extension APIs are detectable by page JS (chrome.runtime exposure)Similar capability but identifiable
mitmproxy + proxyMedium — TLS fingerprint risk; JA3 of mitmproxy's OpenSSL differs from Chrome'sFull visibility including binary uploads

CDP interceptor is the optimal approach for stealth. Extension would not add capability and adds detection surface.
